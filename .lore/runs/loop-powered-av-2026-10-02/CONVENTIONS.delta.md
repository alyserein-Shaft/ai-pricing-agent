# CONVENTIONS shard -- run loop-powered-av-2026-10-02. Terminology discipline for loop-powered vs addressable, and BOQ line vs specification.

- [CONV-2026-10-02-4e91] A DEVICE IS NOT "LOOP POWERED" MERELY BECAUSE IT IS ADDRESSABLE. Four distinct architectures must be named separately and never conflated: (1) an SLC/loop-powered notification appliance that draws its power from the addressable loop AND holds a point address; (2) a conventional NAC appliance with no SLC address; (3) an addressable control module that holds an address and energises NAC appliances from an EXTERNAL supply; (4) a loop-addressed device with separate auxiliary power. Honeywell's own IDP-Control datasheet 350293 Rev H describes supervising "load devices that require an external power supply to operate, such as bells, horns, and strobes", which is case (3) and is how the IDP protocol actually delivers notification. Conflating (1) with (3) is what makes a BOQ label look unsatisfiable when the real answer is an architecture choice. #added:2026-10-02
- [CONV-2026-10-02-8d33] A BOQ DESCRIPTION IS NOT A DEVICE SPECIFICATION, AND A SPEC REQUIREMENT IS NOT A BOQ-LINE REQUIREMENT. The 150 loop-powered BOQ lines (4,380 units, 7 projects) carry no candela, voltage, protocol or manufacturer wording, and the phrase "loop powered" appears nowhere else in the database. The governing candela duty, exterior rating, Class A NAC, output-count and synchronisation requirements come from the project specification, not the BOQ line. Searching only the BOQ for a requirement will report it as absent; searching only the spec will misattribute it to the BOQ. Report which layer a requirement actually came from. #added:2026-10-02
