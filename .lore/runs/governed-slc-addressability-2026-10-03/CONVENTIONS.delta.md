- [CONV-2026-10-03-GOVADDR-READERS] A GOVERNED AUTHORITY NEEDS A READER THAT CAN ACTUALLY REACH IT, AND "IT HAS A CONSUMER" IS NOT PROOF THAT ANYBODY CAN CALL IT. Before adding an authority, check whether the existing consumer is reachable: a resolver parameter that defaults to `null` and is passed as nothing at every live call site makes the authority unreachable in production while its tests pass with a fake. Here that had been true of `resolveAddressModel` at BOTH live call sites, and the second half of the bug was that TWO DIFFERENT ADDRESSABILITY PATHS existed side by side (whole-blob understanding facts vs the approved product attribute), each incomplete, neither contradicting the other, so no test could ever have caught it.
- [CONV-2026-10-03-GOVADDR-SEPARATE-AXIS] WHEN A NEW AUTHORITY IS FED TO AN EXISTING POLICY, GIVE IT A DEDICATED INPUT, NOT A SLOT IN A BAG. Passing the resolved authority through a generic `attributes` object makes it indistinguishable in provenance from the old weak channel later, and any audit asking "which of these two produced this number?" becomes unanswerable. A named parameter keeps the two chains separable at every layer, which is also what makes "an UNRESOLVED authority reproduces the pre-change outcome byte-identically" a testable claim rather than a hopeful one.
- [CONV-2026-10-03-GOVADDR-REGULATORY-CHECK] BEFORE REPORTING A PERSISTED-COLUMN SEARCH THAT RETURNED 0, CONFIRM THE COLUMN EVER HOLDS THAT VALUE. A `0` from `ruleset_version LIKE '%slc-resource-classification%'` looks like evidence and is not: that column stores a different ruleset family entirely. The instinct to report the 0 anyway -- it is at least honest -- is worse than useless, because a reader will reasonably record it as a finding. Check what the column is FOR, then report the carrier that actually is one.
- [CONV-2026-10-03-GOVADDR-SCOPE-COUNTS] ALWAYS SCOPE A PROFILE-COUNT CLAIM TO THE PROJECT AND SAY SO. A DB-wide `LIKE` match on 219 profiles found 12 hits, all from a different project under a classifier two versions older; the honest figure for the project under discussion was 0, and the unqualified 12 would have read as prior progress on the very task being started.
- [CONV-2026-10-03-GOVADDR-SIGPIPE] `node script | tee file | head -N` CAN TRUNCATE `file`, BECAUSE `head` EXITING EARLY SIGPIPES `tee` BEFORE IT HAS WRITTEN EVERYTHING. Every truncated artifact in this repo should be assumed possibly-corrupt until regenerated as `node script > file 2>&1`. Two conclusions in this slice came from partial output before this was noticed.
- [CONV-2026-10-03-GOVADDR-D1-SHIM] THE ASYNC SCOPE HELPERS TAKE A D1-SHAPED OBJECT, NOT A RAW DRIVER. `currentBoqEvidenceCounts(db, { projectId, organizationId = null } = {})` destructures an options OBJECT -- passing a bare project id fails with an opaque bind error. And a read-only shim should expose no `run`/`batch` at all, throwing `READ_ONLY_SHIM`, so a probe cannot write even by accident.
- [CONV-2026-10-03-GOVADDR-ATTRIBUTION] ATTRIBUTE A FAILURE BY REACHABILITY, NOT BY PLAUSIBILITY. The only defensible method available on a dirty shared tree is: does the asserted pattern exist at HEAD, does it exist now, and can the import graph reach the files this change touched. `git stash` was available and deliberately not used -- stashing a shared tree risks a foreign lane's work, and a clean-tree measurement is not worth that price.
