# Run 2026-10-03 — Geometry-first fail-closed benchmark (closes the blank-image defect)

## A. THE FAIL-OPEN DEFECT, ROOT CAUSE AND FIX
- EV-GB-001 | authority | finding | FAIL-OPEN ROOT CAUSE: acceptance authority sat inside the model. With a BLANK image the previous run produced FIREMAN TELEPHONE JACK / CONFIDENCE 100 / CONSISTENT / ACCEPT_FACT while Stage 1 had correctly reported GLYPH_COUNT=0, ENCLOSURE_SHAPE=NONE, OBSERVATION_CONFIDENCE=0. The model discarded a perfect null signal and answered from the legend alone. Prompt wording cannot fix this because the model is authority over its own output and confidence is not evidence. Acceptance authority was therefore moved OUT of the model into a deterministic gate (scripts/benchmark-12-evidence-gate.mjs).
- EV-GB-002 | authority | finding | THE GATE TAKES NO CONFIDENCE INPUT AT ALL, and applyGate is MONOTONICALLY DOWNWARD: it can turn ACCEPT_FACT into KEEP_UNKNOWN but never the reverse. MODEL_CONFIDENCE_IS_NOT_AUTHORITY is structural, not a prompt instruction.
- EV-GB-003 | authority | correction | A REAL INVERTED-LOGIC BUG in the first version of my own gate, found by replay rather than by the adversarial suite. The line `if (eligibleForReasoning && reasons.length) eligibleForAcceptance = false;` meant that when eligibleForReasoning was FALSE (a hard block) the condition was false and ELIGIBLE_FOR_ACCEPTANCE stayed TRUE. The blank-image replay then returned FIREMAN TELEPHONE JACK / ACCEPT_FACT / c100 / CONSISTENT with overrode=false. Fixed by splitting into two EXPLICIT lists (reasoningBlocks, acceptanceBlocks) with eligibleForAcceptance = eligibleForReasoning && acceptanceBlocks.length===0. After the fix the same replay is overridden to UNKNOWN / KEEP_UNKNOWN / c0 / INSUFFICIENT. LESSON: an adversarial suite that always routes blocked cases through forcedBlockedResult instead of applyGate CANNOT detect this class of bug; the override path must be exercised explicitly.

## B. DETERMINISTIC GEOMETRY IS THE ENABLER
- EV-GB-004 | infra | finding | The decisive discriminator between legend (S) SMOKE DETECTOR and schedule [S]C is the ENCLOSURE SHAPE, which never appears in the text layer. That is why a text-only reasoner could not reach it and why a VLM was being asked to do a job the application can do deterministically.
- EV-GB-005 | infra | finding | DETERMINISTIC ENCLOSURE CLASSIFIER, 7/7 on real Al Mousa schedule cells. Primary discriminator is the longest straight ink run relative to cell size: a square draws long straight edges, a circle has none. Measured on identical 28x22pt cells at 6x: BOX enclosures gave longestRun 71-79px (runRatio 0.53-0.60), ROUND enclosures gave 28px (runRatio 0.21). Clean wide separation, no threshold sensitivity. Earlier attempts using corner/edge-midpoint ink DENSITY bands were unreliable (3/7) because bands near the centre sample the LETTER inside the symbol rather than its outline, and because a riser line enters every plan symbol from above and inks the top edge.
- EV-GB-006 | infra | finding | Region type is now DERIVED deterministically from tokens INSIDE the target region only. Using the wider row neighbourhood previously made a GRS PLAN symbol inherit the SCHEDULE row printed above it, reproducing exactly the legend-vs-schedule confusion the classifier exists to prevent. Correct classification on this run: T=PLAN, S+C/S H/HC=SCHEDULE.
- EV-GB-007 | infra | finding | Honesty boundary: the geometry packet is a RASTER proxy measured from rendered ink structure, NOT true PDF vector-operator parsing. It is deterministic and reproducible but it is a measurement, never authority.
