# CONVENTIONS.delta.md

- [CONV-20261004-POLICY-IS-A-VERSIONED-CONSTANT] Policy identity is a versioned constant `BOQ_NORMALIZATION_AUTO_AUTHORITY_V1` in `app/domain/boq-normalization-auto-authority.mjs`. The UI carries a display-only mirror `BOQ_NORMALIZATION_POLICY_ID` in `app/page.tsx` and never becomes a second source of authority.
- [CONV-20261004-NON-HUMAN-AUTHORITY-PAIR] Non-human authority is always the pair `SYSTEM_POLICY` / `AUTO_APPROVED` plus `policy_id`. Human actors remain `omair` / `Omair`. Never mint a synthetic person or reuse the execution session identity as a decision-maker.
- [CONV-20261004-BLOCKER-CODES-ARE-DEDUPED] Blockers are SCREAMING_SNAKE, returned as a de-duplicated `blockers[]` array, with per-check booleans in a parallel `checks{}` map so a caller can see exactly which gate failed without string-matching.
- [CONV-20261004-DEFERRED-FINDINGS-NEVER-BLOCK] Deferred non-blocking findings live in a separate `deferredAmbiguities[]` array, each carrying an explicit `status`. They are NEVER mixed into `blockers[]`, so a deferral can never be mistaken for a refusal.
- [CONV-20261004-AI-PROVENANCE-ONLY-WHEN-INVOKED] `aiProvenance` is optional and recorded only when AI actually ran: `{ provider, model, attempt, latency, schemaValid, evidenceValidationResult, fallbackUsed }`. It is evidence about a classification, never the basis for authority.
- [CONV-20261004-EVALUATOR-TAKES-FLAT-CURRENTNESS-INPUTS] The evaluator signature is one pure function over `{ review, candidates, sourceRows, currentExtractionId, currentDocumentVersionId, sourceSha256 }`. Currentness inputs are TOP-LEVEL, never nested under a `current` object: nesting them silently skips every currentness check and makes a stale review look eligible.
- [CONV-20261004-ANCHORS-ARE-SOURCE-LOCATION-ROWS] Source rows are addressed by `json_extract(source_location,'$.row')`, NOT by `boq_items.sequence`. Comparing against `sequence` yields a false mismatch count and invents phantom mismatches.
- [CONV-20261004-EVALUATE-IS-READ-ONLY] `POST /api/boq-normalization/:reviewId/evaluate-auto-approval` records no decision and applies nothing. It exists so callers can decide whether human review is even needed. `auto-apply` is the only route that writes, and it delegates to the canonical Apply.
- [CONV-20261004-SNAPSHOT-STATE-BEFORE-GOVERNED-WRITES] Live verification uses the `tmp/gov-driver.mjs` harness (`makeEnv`, `call`, `one`) to drive handlers against live D1. Always capture a pre-state snapshot before a governed write so proofs such as "no product taxonomy written" are real comparisons rather than assumptions.
- [CONV-20261004-CLEAN-UP-ORPHANS-BEFORE-RETRY] A failed governed write can leave an orphan output row. Before retrying, prove it is empty and unreferenced (0 child rows, 0 scope refs, 0 use-as-source), remove it, and reset the parent pointer — never retry on top of partial state, because the orphan can hijack currentness resolution.
- [CONV-20261004-FIX-FIXTURES-NOT-GATES] When a test fixture drifts from the real schema, fix the FIXTURE and say so explicitly. Never widen a governance check to make a fixture pass.
- [CONV-20261004-AN-INCONSISTENT-FIXTURE-MASKS-A-REFUSAL] A fixture that mutates a candidate without mutating the rows it derives from makes a correct refusal look like a bug. Fix the fixture's consistency rather than relaxing the check — in this case the canonical Apply rightly refused `NORMALIZATION_QUANTITY_NOT_DERIVABLE`.
- [CONV-20261004-SOURCE-LEVEL-ASSERTIONS-MUST-ENCODE-CURRENT-DESIGN] Source-text assertions on `app/page.tsx` are used only because no client runtime harness exists. They must assert the CURRENT governed design; an assertion encoding a known defect is worse than no assertion, because it actively defends the defect from being fixed.
