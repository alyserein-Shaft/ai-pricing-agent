# DECISIONS shard -- run idp-control-6-addresses-2026-10-02. Proven IDP-CONTROL / IDP-CONTROL-6 SLC address consumption, and how a multi-point count is represented.

- [DEC-2026-10-02-3b74] `IDP-CONTROL-6` CONSUMES SIX SLC ADDRESSES, PROVEN FOUR INDEPENDENT WAYS FROM `LS10179-000FH-E:B`. Section 6.4.2: "each IDP-CONTROL-6 and SK-CONTROL-6 module can be set to one of 154 base addresses (01-154). The remaining module points are automatically assigned to the next five higher SLC addresses. For example, if the base address is set to 28, the next five module points will be addressed to 29, 30, 31, 32 and 33." Section 6.4.5: "as shipped, all six addresses are disabled". Figure 6.7 provides six address switches (#1-#6) with "status ... of each module address". And the arithmetic closes: 154 + 5 = 159, exactly the module-address ceiling from 5.2.1, so the base range and the ceiling are only consistent with a 6-address block. The device is ONE physical SLC module holding a CONTIGUOUS BLOCK of six point addresses. Standalone `IDP-CONTROL` remains ONE address (6.2.1 routes it to the "Single Point" procedure, whose range is the full 01-159). #added:2026-10-02
- [DEC-2026-10-02-6a19] A MULTI-POINT ADDRESS COUNT IS SUPPLIED EXPLICITLY, NEVER ENCODED IN THE ADDRESS-MODEL VOCABULARY. `ADDRESS_MODEL_SLC_DEMAND` still holds exactly five tokens and no token exceeds `additionalAddressesConsumed: 1`, because the count varies per product (6 for the control/zone/relay -6 modules, 10 for IDP-MONITOR-10) and a token cannot carry a per-product number. Instead `slcAddressDemandForItem` accepts an optional explicit `addressesConsumed`, validated as a positive integer and refused with the new `ADDRESS_COUNT_INVALID` otherwise, so a malformed count fails closed rather than silently falling back to one. The token remains authoritative for WHETHER an address is consumed and WHICH pool it lands in; the explicit count supplies only HOW MANY. An explicit count can never raise a zero-address device above zero, so notification appliance quantity cannot become an SLC address count. #added:2026-10-02
