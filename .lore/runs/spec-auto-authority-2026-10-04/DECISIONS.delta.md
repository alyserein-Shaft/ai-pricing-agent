# DECISIONS.delta.md

- [DEC-20261004-SPEC-AUTO-AUTHORITY-REUSES-CANONICAL-FLOOR] `SPEC_AUTO_AUTHORITY_V1` is an INTERSECTION: it REUSES the proven `spec-requirement-auto-confirm-1.0.0` 12-gate evaluator as a mandatory floor and ADDS provenance/currentness gates. It never widens it. The canonical floor additionally requires `requirement_type = Mandatory` AND an exact normative modal in the ORIGINAL TEXT and refuses weak phrasing, commercial boilerplate, delegated design-choice language and Documentation/Maintenance/Training. Those refusals are deliberate and were NOT overturned: approving a sentence that merely says a system shall be "suitable" or "as required" would assert non-binding or non-technical language as approved downstream technical truth.
- [DEC-20261004-SPEC-CONFIDENCE-WITHHOLDS-NEVER-GRANTS] `confidence` is never read by the policy. The ONLY confidence-derived input is the explicit `confidence_state = 'Needs Review'` doubt flag, and it is used exclusively to REFUSE. A doubt signal can withhold authority but can never confer it, which is the opposite of letting model confidence decide. Test 8 pins both directions: a numeric score of 1 must not block, and a numeric score of 100 must not override a doubt flag.
- [DEC-20261004-SPEC-REVISION-RESOLVED-NOT-COPIED] Revision identity is RESOLVED through requirement -> `extraction_version_id` -> `specification_extraction_versions.document_version_id` -> `documents.current_version_id`. It is never read from the requirement row (`source_revision` is 0/505 and is never consulted) and never accepted from a client string. Missing / unknown / superseded / incomplete extraction, or a deleted or archived source document, each fail closed for the affected row.
- [DEC-20261004-SPEC-EXTRACTION-DOUBT-IS-A-GATE] A flagged extraction doubt (`confidence_state = 'Needs Review'`, 92 rows) blocks auto-authority. This is fail-closed use of a doubt signal, not authority from a score.
- [DEC-20261004-SPEC-NON-ELIGIBLE-IS-NOT-HUMAN-REQUIRED] A requirement that fails a deterministic gate is classified `SEMANTIC_REASONING_REQUIRED` (322) or `AMBIGUOUS_OR_CONFLICTED` (23) or `STALE_OR_REFUSED` (0). None is permanently classified as human-required; the semantic population is routed to the AI Project Evidence Reasoner for a later governed pass.
- [DEC-20261004-SPEC-SINGLE-CANONICAL-WRITER] The policy creates NO parallel approval writer. It delegates to `autoConfirmSpecRequirement`, which performs a real compare-and-swap guarded by `currentTechnicalRequirementsFrom` EXISTS currency and writes its audit row only after the transition commits. A refused write is reported as refused, never as success.
- [DEC-20261004-SPEC-EVIDENCE-IS-ATOMIC-OR-IT-CANNOT-EXIST] `requirement_review_decisions` is APPEND-ONLY, enforced by `requirement_review_decisions_immutable_update` and `_immutable_delete` triggers that RAISE(ABORT). Governance provenance therefore CANNOT be annotated after a transition. The canonical writer was extended with an optional `evidence` parameter so a calling policy's authority is written ATOMICALLY with the transition it authorises. A post-hoc UPDATE approach is impossible by design and must never be attempted.
- [DEC-20261004-SPEC-TRANSITION-ACTOR-VS-GOVERNING-POLICY] `decided_by` records who performed the write (`system:spec-requirement-auto-confirm`, the canonical writer's actor); `evidence.governingPolicy` records which policy gated it (`SPEC_AUTO_AUTHORITY_V1`). Matching the audit row on the canonical actor is correct, not a bug: the writer and the gate are different facts.
