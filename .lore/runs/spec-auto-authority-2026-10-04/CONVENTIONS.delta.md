# CONVENTIONS.delta.md

- [CONV-20261004-SPEC-POLICY-SHAPE] Policy identity is a versioned constant in `app/domain/spec-auto-authority.mjs`: `SPEC_AUTO_AUTHORITY_POLICY`, `SPEC_AUTO_AUTHORITY_ACTOR_TYPE` (`SYSTEM_POLICY`), `SPEC_AUTO_AUTHORITY_ACTOR` (`system:spec-auto-authority-v1`, always `system:`-prefixed), plus `SPEC_SEMANTIC_REASONING_REQUIRED`, `SPEC_AMBIGUOUS_OR_CONFLICTED`, `SPEC_STALE_OR_REFUSED`.
- [CONV-20261004-SPEC-GATE-AND-CLASSIFICATION-NAMING] Every evaluation returns `gates[]` (each with `name`, `pass`, `reason`), `failedGates[]`, and exactly one `classification`. A refusal always names WHY; nothing is silently parked. Ambiguity and conflict findings are never merged into the gate list.
- [CONV-20261004-SPEC-ORCHESTRATOR-SUPPORTS-DRY-RUN] `runSpecAutoAuthority(db, { projectId, apply })` defaults to a read-only dry run that records no decision. `apply: true` is the only path that writes, and it delegates each write to the canonical writer.
- [CONV-20261004-SPEC-REVISION-CACHE-POPULATION-SAFE] The orchestrator resolves revision per distinct `extraction_version_id` and caches it, so a population spanning several extractions can never launder a stale binding through a single global assumption. It passes `activeExtractionVersionId: null` for any requirement whose binding is unresolved or not current, so the canonical gate independently refuses it.
- [CONV-20261004-AUDIT-TABLE-IS-APPEND-ONLY] `requirement_review_decisions` rejects UPDATE and DELETE via triggers. Before designing any writer or annotation path against it, read the triggers. Provenance must be supplied at INSERT time.
- [CONV-20261004-VERIFY-TEXT-BY-ORDERED-DIGEST] Never compare requirement text with `group_concat`, whose ordering is unspecified and produces false diffs after an UPDATE. Compare an ordered per-row SHA-256 digest, and additionally confirm the writer's SQL never references a text column.
